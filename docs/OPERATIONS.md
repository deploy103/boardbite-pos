## 1. 행사 시작 전 준비 (하루 전에 미리 하기)

1. 관리자(ADMIN) 계정으로 로그인해서 다음이 잘 되어 있는지 확인합니다.
   - **메뉴 탭**: 팔 메뉴가 전부 등록되어 있고 가격이 맞는지 확인합니다.
   - **테이블 탭**: 사용할 테이블 번호가 전부 등록되어 있는지 확인합니다.
   - **이용권 탭**: 보드게임 이용 시간(10분/20분/30분 등)과 가격이 맞는지 확인합니다.
   - **결제수단 탭**: 현금/카드 외에 추가로 받을 결제수단이 있으면 미리 등록합니다.
   - **사용자 탭**: FRONT/POS/SERVING 담당 학생마다 계정이 필요하면 미리 만들어 둡니다(비밀번호는 초기 로그인 후 꼭 바꾸도록 안내합니다).
2. 각 테이블에 붙일 QR 스티커를 인쇄합니다. **테이블 탭**에서 각 테이블의 "주문 URL"을 확인해 QR 코드로 만들어 인쇄한 뒤 실제 테이블에 붙입니다.
3. 태블릿/PC/휴대폰이 전부 같은 와이파이(또는 같은 네트워크)에 연결되어 있는지 확인합니다.

## 2. 서버 시작/종료

**시작**

1. 서버용 컴퓨터에서 터미널(명령창)을 엽니다.
2. 아래 두 명령을 각각 다른 터미널 창에서 실행합니다.
   ```
   npm run dev:server
   ```
   ```
   npm run dev:client
   ```
3. "listening on port 3000"과 "ready" 글자가 보이면 정상적으로 시작된 것입니다.
4. 같은 와이파이에 연결된 다른 기기에서 `http://서버컴퓨터의IP주소:5173`으로 접속되는지 확인합니다.

**종료**

- 각 터미널 창에서 `Ctrl + C`를 누르면 서버가 종료됩니다.
- 갑자기 꺼야 할 때는 그냥 창을 닫아도 되지만, 가능하면 `Ctrl + C`로 정상 종료하는 것을 권장합니다.

## 3. 직원 로그인

1. 아무 기기에서나 브라우저로 서버 주소의 `/staff/login`으로 들어갑니다(예: `http://서버주소:5173/staff/login`).
2. 미리 안내받은 아이디/비밀번호를 입력합니다.
3. 로그인하면 자동으로 담당 화면(관리자/프론트/주방/서빙)으로 이동합니다. **화면을 직접 고르지 않아도 됩니다.**
4. 처음 로그인했는데 "비밀번호를 바꿔주세요" 안내가 보이면, 관리자에게 비밀번호를 새로 받아서 다시 로그인합니다.

## 4. 자리 배정과 테이블 열기(OPEN)

1. FRONT 계정으로 로그인하면 테이블 현황 화면이 보입니다.
2. 손님이 오면 빈 테이블(초록색 "빈자리" 표시)을 찾아 **"자리 배정"** 버튼을 누릅니다.
3. 인원수를 입력하고, 보드게임을 이용한다면 이용권(예: "20분")을 선택합니다.
4. **"테이블 열기"** 버튼을 누르면 그 순간부터 손님이 QR을 찍어 주문할 수 있습니다.
5. **테이블을 열기 전에는 QR을 찍어도 주문이 안 됩니다.** 손님이 "주문이 안 돼요"라고 하면 먼저 테이블이 열려 있는지 확인하세요.

## 5. NFC/QR 문제 대응

- **QR을 찍었는데 "현재 주문 가능한 테이블이 아닙니다"라고 나올 때**: 그 테이블이 아직 열리지 않았거나, 이미 정산이 끝난 테이블입니다. FRONT 화면에서 테이블 상태를 확인하고, 필요하면 자리 배정을 먼저 합니다.
- **QR이 찍히지 않거나 스티커가 훼손됐을 때**: 관리자(ADMIN) 화면의 테이블 탭에서 "토큰 회전"을 누르면 그 테이블의 새 QR 주소가 발급됩니다. QR 코드를 다시 인쇄해서 붙여야 합니다(이전 QR은 더 이상 동작하지 않습니다).
- **손님이 화면을 새로고침했는데 처음부터 다시 시작될 때**: 정상입니다. 서버가 항상 최신 상태를 다시 불러오므로 걱정하지 않아도 됩니다.

## 6. 주방(POS) 화면 사용법

1. POS 계정으로 로그인하면 주문 보드가 보입니다. 화면은 **신규 / 접수 / 조리중 / 준비완료** 4개 칸으로 나뉩니다.
2. 새 주문이 들어오면 "신규" 칸에 나타나고 알림음이 울립니다(알림음이 시끄러우면 화면 위쪽의 알림음 버튼으로 끌 수 있습니다).
3. 주문을 만들 수 있으면 **"접수"**를 누릅니다. 재료가 없거나 문제가 있으면 **"거부"**를 눌러 사유를 선택합니다.
4. 조리를 시작하면 **"조리 시작"**을 누릅니다.
5. 다 만들었으면 **"준비완료"**를 누릅니다. 이제 서빙 담당자 화면에 나타납니다.
6. 카드 테두리가 노란색이면 "조금 오래 걸리고 있다"는 뜻이고, 빨간색이면 "많이 지연되고 있다"는 뜻입니다. 색이 없어도 카드에 글자로 "임박"/"지연"이라고 표시되니 색이 잘 안 보여도 확인할 수 있습니다.
7. **"이력"** 탭에서 예전 주문을, **"거부/취소"** 탭에서 취소된 주문을 찾아볼 수 있습니다.
8. 메뉴가 다 팔렸으면 **"품절 처리"** 탭에서 바로 품절로 바꿀 수 있습니다.

## 7. 서빙 화면 사용법

1. SERVING 계정으로 로그인하면 준비완료(READY)된 주문 목록이 테이블별로 보입니다.
2. 음식을 가져다주고 나서 **"서빙 완료"**를 누릅니다.
3. 실수로 잘못 눌렀다면 **"최근 서빙완료"** 탭에서 **"되돌리기"**를 누를 수 있습니다. 단, 누른 지 너무 오래 지나면(기본 3분) 되돌릴 수 없고, 이때는 관리자에게 부탁해야 합니다.
4. 오래 기다리고 있는 주문은 카드가 강조되어 표시됩니다.

## 8. 직원 호출 처리

1. 손님이 자기 화면에서 "직원 호출하기"를 누르면 서빙 화면의 **"직원 호출"** 영역에 나타납니다.
2. 확인했으면 **"확인"**을 눌러 손님에게 "직원이 확인했어요"가 보이게 합니다.
3. 처리가 끝나면 **"완료"**를 눌러 목록에서 지웁니다.

## 9. 정산(계산) 방법

손님이 나갈 때 FRONT 화면에서 해당 테이블의 **"정산"** 버튼을 누르면 정산 화면으로 들어갑니다.

- **금액으로 결제**: 부분결제/복합결제를 할 때 씁니다. 현금이면 손님에게 받은 금액을 입력하면 거스름돈이 자동으로 계산됩니다("정확히"/"+1,000"/"+5,000"/"+10,000"/직접입력 버튼 사용 가능). 카드나 기타 결제는 남은 금액을 넘겨서 받을 수 없습니다.
- **더치페이**: 인원수를 입력하면 1/N로 나눈 금액을 보여줍니다(나누어떨어지지 않으면 몇 명은 1원씩 더 냅니다). 각자 자기 몫을 결제 버튼으로 처리합니다.
- **상품별 결제**: 손님별로 자기가 먹은 메뉴만 골라서 결제할 수 있습니다. 같은 메뉴가 2개면 1개만 결제하는 것도 가능합니다. 이미 결제된 수량은 다시 선택할 수 없습니다.
- **할인**: "할인 적용" 버튼으로 금액과 사유를 입력하면 남은 금액에서 빠집니다.
- 남은 금액이 정확히 0원이 되면 **자동으로 테이블이 정리되고 다음 손님을 받을 수 있는 상태로 바뀝니다.** 따로 "정산 완료" 버튼을 누를 필요가 없습니다.
- 아직 조리/서빙이 안 끝난 메뉴가 있는 상태로 완납하면 "완납했지만 서빙 대기 중"이라는 안내가 뜨고, 서빙이 다 끝나면 그때 자동으로 테이블이 정리됩니다.

## 10. 잘못 결제했을 때 취소하는 방법

1. 정산 화면 아래쪽 **"결제 내역"**에서 잘못된 결제를 찾습니다.
2. 그 결제 옆의 **"취소"** 버튼을 누르고 사유를 입력합니다.
3. 취소하면 그만큼 남은 금액이 다시 늘어납니다. 이미 다음 손님을 받은 뒤에 취소하면 "환불"로 기록되며, 이 경우 실제 환불은 직원이 직접 손님에게 전달해야 합니다(시스템이 자동으로 돈을 돌려주지는 않습니다).

## 11. 테이블 강제로 닫기(CLOSE)

정산이 애매하거나 손님이 그냥 가버린 경우, FRONT 화면에서 **"테이블 종료"** 버튼으로 강제로 닫을 수 있습니다. 이 경우 미수금이 있어도 테이블은 빈자리로 바뀌니, 미수금 내역은 관리자 화면의 "결제내역"/"매출현황"에서 나중에 확인할 수 있습니다.

## 12. 품절 처리

- 주방(POS)에서: **"품절 처리"** 탭에서 즉시 처리(가장 빠릅니다).
- 관리자(ADMIN)에서: **"메뉴"** 탭에서도 품절 처리와 가격 변경, 메뉴 추가/수정을 할 수 있습니다.

## 13. 네트워크가 끊겼을 때

- 화면들은 몇 초마다 자동으로 서버와 다시 동기화하도록 만들어져 있습니다. 와이파이가 잠깐 끊겼다가 다시 연결되면 자동으로 최신 상태로 돌아옵니다. **새로고침을 억지로 할 필요는 없습니다.**
- 그래도 화면이 이상하면 새로고침(브라우저 새로고침 버튼)을 한 번 눌러보세요. 로그인 상태와 테이블 상태는 서버에 저장되어 있으므로 새로고침해도 데이터가 사라지지 않습니다.
- 서버 컴퓨터 자체가 꺼지거나 멈추면 모든 기기에서 화면이 멈춥니다. 이 경우 [2. 서버 시작/종료]를 참고해 서버를 다시 켭니다. **서버를 다시 켜도 지금까지의 주문/결제 데이터는 그대로 남아 있습니다.**

## 14. 중간 점검(운영 중 확인 사항)

- 관리자 화면의 **"매출현황"** 탭에서 지금까지의 매출, 결제수단별 금액, 잘 팔린 메뉴를 수시로 확인할 수 있습니다.
- 문제가 생기면 **"결제내역"**과 **"감사 로그"** 탭에서 누가 언제 무엇을 했는지 찾아볼 수 있습니다.
- 특정 테이블에 문제가 있으면(예: 이상한 주문이 계속 들어옴) 관리자 화면의 테이블 탭에서 그 테이블만 "주문 잠금" 또는 "결제 잠금"을 걸 수 있습니다. 행사 전체에 문제가 있으면 **"운영설정"** 탭에서 "전체 주문받기"/"전체 결제받기"를 통째로 꺼둘 수 있습니다.

## 15. 마감 절차

1. 마지막 손님까지 정산을 끝냅니다.
2. 관리자 화면의 **"매출현황"**에서 오늘 총 매출과 결제수단별 매출을 확인하고 사진을 찍어두거나 화면을 캡처해둡니다.
3. **"매출현황" → CSV 내보내기**(또는 감사 로그 탭의 CSV 내보내기)로 정산 기록을 파일로 저장해둡니다.
4. [16. 백업하는 방법]에 따라 데이터를 백업합니다.
5. 서버를 종료합니다.

## 16. 백업하는 방법

1. 관리자 화면의 **"백업"** 탭에서 **"백업 생성"** 버튼을 누릅니다.
2. 백업이 만들어지면 목록에 나타나고, 그 항목을 눌러 파일로 내려받을 수 있습니다.
3. 내려받은 파일은 USB나 클라우드 등 서버 컴퓨터가 아닌 다른 곳에도 꼭 하나 더 보관해두세요(서버 컴퓨터가 고장 나면 그 안의 백업도 같이 사라집니다).
4. **트래픽이 적을 때(마감 직후 등) 백업하는 것을 권장합니다.** 손님이 한창 몰릴 때 백업하면 아주 드물게 그 순간의 결제 한 건이 백업 파일에 반영되지 않을 수 있습니다.

## 17. 다음 날 초기화

같은 행사를 여러 날 진행한다면:

- 테이블/메뉴/직원 계정은 그대로 둡니다(다시 만들 필요 없음).
- 전날 열린 채로 남은 테이블이 있다면 FRONT 화면에서 **"테이블 종료"**로 정리합니다.
- 완전히 새로운 행사로 시작하고 싶다면(예: 다른 학교/다른 학기), 개발자에게 데이터베이스 초기화를 요청하세요. 이 문서만으로는 데이터 전체 초기화를 진행하지 않는 것을 권장합니다(실수로 실제 매출 기록이 사라질 수 있습니다).
